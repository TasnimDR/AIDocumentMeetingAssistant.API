Framework = Cadre de travail.
Composer  = Outil de gestion de dépendances PHP (Crée un fichier intitulé composer.json contient la liste des dépendances du projet).
CLI = Outil de développement qui aide à créer, exécuter et gérer les applications Symfony à partir du teminal.
MVC = Séparer les requêtes de la base de données (Model), dela logique relative au traitement des demandes (Controller), et à l'affichage (View).
Controller = Traiter la requête de l'utilisateur et générer une réponse.
Model = Gérer les données.
View = Afficher les données récupérées du Model.
/bin = Les fichiers exécutables.
/config = La configuration de l'application Symfony (routes,services...).
/public = Les fichiers accessibles au public + contrôleur frontal.
/src = Entity + Controller + Form.
/templates = Les pages qui vont être affichées à l'écran (.htm.twig)
/test = Les test automatiques.
/vendor = Les dépendances de notre projet.
.env = La configuration de l'environnement d'exécution.
Flux applicatif d'une requête :
	1- Le visiteur demande l'URL /student.
	2- Le contrôleur frontal va charger Kernel et lui trasmet l'URL.
	3- Le Kernel appel le Routeur pour savoir quel contrôleur exécute l'URL.
	4- Le Routeur cherche le contrôleur à exécuter et l'envoie au Kernel.
	5- Le Kernel appel ce contrôleur.
	6- Ce contrôleur demande du modèle les données et les donne à la vue pour l'affichage.
	7- Le contrôleur transmet la page HTML au visiteur.
Contrôleur frontal = Le fichier par lequel passent toutes les pages.
Route = Faire correspondre une URL et une action d'un contrôlleur.
Routeur = Chercher la route qui correspond à l'URL appelée et retourner les paramètres de cette route.
Symfony Flex = Un pulgin Compsoer qui permet d'exécuter des tâches sur certaines commandes Composer et permet d'automatiser l'installation et la supression des dépendances en fournissant une configuration par défaut et laisse une trace des recette qu'il a installées dans un fichier appelé symfony.lock
MakerBundle = Créer de commandes vides, des contrôleurs, des classes de formulaire etc...

Chapitre 3 :
------------
ORM/ Object-Rleational Mapping = Faire la relation entre les données orientées objet et les données relationnelles.
Doctrine = Un ORM
Configuration de l'entité :
	#[ORM\Id] => Spécifie la clé primaire.
	#[ORM\GeneratedValue] => Auto-incrémentation de l'ID.
	#[ORM\Column] => Définir les caractéristiques de la colonne concernée.
La Migration = Tracker les différents changements et évolutions de la base de données et génère un fichier de migration (le nom du fichier sera stocké dans la bd table: doctrine_migration_versions).
Le Repository = Une classe PHP qui contient les méthodes de récupération de données relatives aux entités.
EM/ Entity Manager = Un gestionnaire d'entités placée entre les objets et les tables de la base de données qui permet l'insertion, la mise à jour et la suppression des données de la base de données.

Supression :

#[Route('/supprimeC/{id}', name: 'supprimeC')]
    public function supprimeC($id, ClassroomRepository $repository, ManagerRegistry $doctrine): Response
    {
        $c=$repository->find($id);

        $em=$doctrine->getManager();
        $em->remove($c);
        $em->flush();

        return $this->redirectToRoute('afficheC');
    }

Ajout :

#[Route('/ajoutC', name: 'ajoutC')]
    public function ajoutC(ManagerRegistry $doctrine, Request $request)
    {
        $classroom=new Classroom();
        $form=$this->createForm(ClassroomFormType::class,$classroom);
        $form->handleRequest($request);
        if($form->isSubmitted())
        {
            $em=$doctrine->getManager();
            $em->persist($classroom);
            $em->flush();
            return $this->redirectToRoute("afficheC");
        }
        return $this->renderForm('classroom/ajoutC.html.twig', 
            array("f"=>$form)
        );
    }
